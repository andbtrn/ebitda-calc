# Калькулятор мотивации по EBITDA — Спецификация

## A1. Обзор продукта и роли

### Описание продукта

Веб-приложение для расчёта и управления системой мотивации руководителя (директора) на основе показателей EBITDA компании. Система позволяет настраивать параметры мотивационной схемы, вводить фактические данные по EBITDA помесячно, автоматически рассчитывать бонусы (удержание + рост), управлять "банком" отложенных выплат, проводить квартальные и годовые закрытия с выплатами. Все изменения версионируются и аудитируются.

### Роли

| Роль | Описание | Права |
|------|----------|-------|
| **Админ** | Владелец workspace или назначенный администратор | Полный доступ: настройки, ввод данных, выплаты, корректировки банка, закрытие периодов, просмотр аудита |
| **Пользователь** | Участник workspace с правами просмотра | Просмотр всех данных (месяцы, банк, настройки), без права изменения |

### UC-04: Ввод EBITDA по месяцам

**Актёр:** Админ
**Предусловия:** Workspace существует, год не закрыт
**Шаги:**
1. Переход на вкладку "Месячные расчёты"
2. Выбор года

**Ожидаемое поведение:**
- Значение сохраняется

### UC-07: Правка прошлого месяца с пересчётом

**Актёр:** Админ
**Предусловия:** Месяц не заблокирован, год не закрыт
**Шаги:**
1. Изменение EBITDA за прошлый месяц (например, март при текущем июне)
2. Сохранение

**Ожидаемое поведение:**
- Пересчёт марта
- Пересчёт банка с марта по декабрь (running balance)
- Пересчёт Q1, Q2 и года
- Запись в аудит с пометкой "правка задним числом"
- Если были выплаты после марта — они НЕ откатываются, но создаётся информационное уведомление

### UC-08: Квартальное закрытие и выплата

**Актёр:** Админ
**Предусловия:** Все месяцы квартала введены
**Шаги:**
1. Переход на вкладку "Банк и выплаты"
2. Выбор квартала
3. Проверка условия квартала
4. Нажатие "Выполнить квартальную выплату"
5. Подтверждение

**Ожидаемое поведение:**
- Проверка условия: `EBITDA_Q >= (annual_base/4) * (1 + quarterly_condition_pct)`
- Если условие не выполнено → ошибка "Условие квартала не выполнено"
- Если условие выполнено:
  - Расчёт суммы выплаты по методу (quarter_accrual или current_balance)
  - Создание записи в ledger с типом `quarter_payout`
  - Уменьшение bank_balance
  - Запись в аудит
- Повторная попытка → ошибка "Выплата за этот квартал уже выполнена"

---

### UC-09: Годовое закрытие и выплата

**Актёр:** Админ
**Предусловия:** Все 12 месяцев введены
**Шаги:**
1. Переход на вкладку "Банк и выплаты"
2. Проверка условия года
3. Нажатие "Закрыть год и выплатить остаток"
4. Подтверждение (с предупреждением о необратимости)

**Ожидаемое поведение:**
- Проверка условия: `EBITDA_year >= annual_base * (1 + year_condition_pct)`
- Если условие не выполнено → ошибка "Условие года не выполнено. Остаток банка сгорает."
- Если условие выполнено:
  - Выплата всего остатка банка
  - Запись в ledger с типом `year_payout`
  - Пометка года как `closed=true`
  - Запись в аудит
- После закрытия: правки месяцев и настроек для этого года запрещены

---

### UC-10: Ручная корректировка банка

**Актёр:** Админ
**Предусловия:** Год не закрыт
**Шаги:**
1. Переход на вкладку "Банк и выплаты"
2. Нажатие "Ручная корректировка"
3. Ввод суммы (положительной или отрицательной)
4. Ввод обязательного комментария
5. Подтверждение

**Ожидаемое поведение:**
- Создание записи в ledger с типом `manual_adjustment`
- Обновление bank_balance
- Запись в аудит с комментарием

---

### UC-11: Попытка повторной выплаты

**Актёр:** Админ
**Предусловия:** Выплата за период уже выполнена
**Шаги:**
1. Попытка выполнить квартальную/годовую выплату повторно

**Ожидаемое поведение:**
- Система отклоняет операцию
- Сообщение: "Выплата за Q{N} {год} уже выполнена" или "Год {год} уже закрыт"
- Идемпотентность обеспечена уникальным constraint

---

### UC-12: Обработка неполных данных и отрицательной EBITDA

**Актёр:** Админ
**Предусловия:** Часть месяцев без данных или с отрицательной EBITDA
**Шаги:**
1. Ввод данных не по всем месяцам
2. Ввод отрицательного значения EBITDA

**Ожидаемое поведение:**
- Месяцы без EBITDA: расчётные поля = 0, помечены как "Нет данных"
- Отрицательная EBITDA: допустима, retention = 0, growth = 0
- Квартальная выплата недоступна, если не все месяцы квартала введены
- Годовая выплата недоступна, если не все 12 месяцев введены

---

### UC-13: Смена конфигурации в середине года

**Актёр:** Админ
**Предусловия:** Год частично заполнен, есть выплаты
**Шаги:**
1. Создание новой версии конфигурации с изменёнными ставками
2. Назначение конфигурации текущему году с месяца N
3. Подтверждение

**Ожидаемое поведение:**
- Месяцы до N остаются на старой конфигурации
- Месяцы с N пересчитываются по новой конфигурации
- Если были выплаты — создаётся компенсирующая запись или уведомление
- Запись в аудит

---

### UC-14: Просмотр аудита

**Актёр:** Админ или Пользователь
**Предусловия:** Есть записи в аудите
**Шаги:**
1. Переход на вкладку "Банк и выплаты" → раздел "История операций"
2. Фильтрация по периоду или типу

**Ожидаемое поведение:**
- Отображение всех операций с ledger
- Для каждой записи: дата, тип, сумма, комментарий, кто выполнил

## A3. Формулы и правила расчёта

### Базовые параметры

```
monthly_base = annual_ebitda_base / 12
monthly_threshold = monthly_base * (1 + kpi_growth_threshold_pct)
quarter_base = annual_ebitda_base / 4
quarter_threshold = quarter_base * (1 + quarterly_condition_pct)
year_threshold = annual_ebitda_base * (1 + year_condition_pct)
```

### Удержание (retention)

```
если EBITDA < monthly_base:
    retention = 0

если monthly_base <= EBITDA <= monthly_threshold:
    retention = retention_max * (EBITDA - monthly_base) / (monthly_threshold - monthly_base)

если EBITDA > monthly_threshold:
    retention = retention_max
```

### Рост (growth_bonus)

**Обычный режим (tiered_growth_enabled = false):**
```
growth_bonus = growth_rate * max(0, EBITDA - monthly_threshold)
```

**Градационный режим (tiered_growth_enabled = true):**
```
growth_bonus = 0
для каждой зоны в tiered_growth_json:
    zone_from = threshold если "threshold" иначе числовое значение
    zone_to = значение или +∞

    если EBITDA > zone_from:
        taxable = min(EBITDA, zone_to) - zone_from
        growth_bonus += taxable * zone.rate
```

### Итого бонус

```
total_bonus = retention + growth_bonus
```

### Split (разделение на выплату и банк)

```
paid_now = round(total_bonus * (1 - bank_split_pct))
to_bank = round(total_bonus * bank_split_pct)
```

Примечание: `paid_now + to_bank` может отличаться от `total_bonus` на 1 рубль из-за округления. Это допустимо.

### Остаток банка (running balance)

```
bank_balance[month] = bank_balance[month-1] + to_bank[month] - payouts[month]
```

Для января: `bank_balance[0] = carryover_from_previous_year` (по умолчанию 0).

### Квартальная выплата

**Условие:**
```
EBITDA_Q1 = EBITDA_jan + EBITDA_feb + EBITDA_mar
condition_met = EBITDA_Q >= quarter_base * (1 + quarterly_condition_pct)
```

**Сумма к выплате:**
```
если quarter_payout_method = "quarter_accrual":
    available = quarter_payout_pct * (to_bank_jan + to_bank_feb + to_bank_mar)

если quarter_payout_method = "current_balance":
    available = quarter_payout_pct * current_bank_balance
```

### Годовая выплата

**Условие:**
```
EBITDA_year = сумма EBITDA за 12 месяцев
condition_met = EBITDA_year >= annual_ebitda_base * (1 + year_condition_pct)
```

**Сумма:** весь остаток банка.

**Если условие не выполнено:** остаток банка обнуляется (сгорает).

### Округление

- Все денежные значения хранятся как `integer` (целые рубли)
- Округление: `round()` (математическое, до ближайшего целого)
- При отображении: форматирование с разделителями тысяч

## A4. Модель данных PostgreSQL

### Диаграмма связей

```
users (Supabase Auth)
    │
    └──< memberships >── workspaces
                              │
                              ├──< configs
                              │
                              ├──< year_configs >── configs
                              │
                              ├──< months >── configs
                              │
                              ├──< quarters
                              │
                              ├──< years
                              │
                              ├──< ledger
                              │
                              └──< audit
```

### Таблица: workspaces

```sql
CREATE TABLE workspaces (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now(),
    created_by UUID REFERENCES auth.users(id)
);
```

### Таблица: memberships

```sql
CREATE TABLE memberships (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,
    user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
    role TEXT NOT NULL CHECK (role IN ('admin', 'viewer')),
    created_at TIMESTAMPTZ DEFAULT now(),
    UNIQUE (workspace_id, user_id)
);
```

### Таблица: configs (версии конфигураций)

```sql
CREATE TABLE configs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,
    version INTEGER NOT NULL,
    name TEXT, -- например "2026 v2"

    -- Параметры (все в JSON для гибкости или отдельными полями)
    fixed_monthly INTEGER NOT NULL DEFAULT 180000,
    annual_ebitda_base INTEGER NOT NULL DEFAULT 10000000,
    kpi_growth_threshold_pct NUMERIC(5,4) NOT NULL DEFAULT 0.10,
    retention_max INTEGER NOT NULL DEFAULT 80000,
    growth_rate NUMERIC(5,4) NOT NULL DEFAULT 0.25,
    bank_split_pct NUMERIC(5,4) NOT NULL DEFAULT 0.50,
    quarter_payout_pct NUMERIC(5,4) NOT NULL DEFAULT 0.50,
    quarterly_condition_pct NUMERIC(5,4) NOT NULL DEFAULT 0.00,
    year_condition_pct NUMERIC(5,4) NOT NULL DEFAULT 0.10,
    tiered_growth_enabled BOOLEAN NOT NULL DEFAULT false,
    tiered_growth_json JSONB DEFAULT '[]',
    quarter_payout_method TEXT NOT NULL DEFAULT 'quarter_accrual'
        CHECK (quarter_payout_method IN ('quarter_accrual', 'current_balance')),

    created_by UUID REFERENCES auth.users(id),
    created_at TIMESTAMPTZ DEFAULT now(),

    UNIQUE (workspace_id, version)
);
```

### Таблица: year_configs (привязка конфигурации к году)

```sql
CREATE TABLE year_configs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,
    year INTEGER NOT NULL,
    config_id UUID REFERENCES configs(id),
    effective_from_month INTEGER NOT NULL DEFAULT 1 CHECK (effective_from_month BETWEEN 1 AND 12),
    locked BOOLEAN NOT NULL DEFAULT false, -- год закрыт
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now(),

    UNIQUE (workspace_id, year, effective_from_month)
);
```

### Таблица: months

```sql
CREATE TABLE months (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,
    year INTEGER NOT NULL,
    month INTEGER NOT NULL CHECK (month BETWEEN 1 AND 12),

    -- Входные данные
    ebitda INTEGER, -- NULL = не введено
    comment TEXT,
    locked BOOLEAN NOT NULL DEFAULT false,

    -- Расчётные поля (заполняются при пересчёте)
    config_id UUID REFERENCES configs(id),
    monthly_base INTEGER,
    monthly_threshold INTEGER,
    retention INTEGER DEFAULT 0,
    growth_bonus INTEGER DEFAULT 0,
    total_bonus INTEGER DEFAULT 0,
    paid_now INTEGER DEFAULT 0,
    to_bank INTEGER DEFAULT 0,
    bank_balance_after INTEGER DEFAULT 0, -- остаток банка после этого месяца

    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now(),

    UNIQUE (workspace_id, year, month)
);

CREATE INDEX idx_months_workspace_year ON months(workspace_id, year);
```

### Таблица: quarters (агрегаты кварталов)

```sql
CREATE TABLE quarters (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,
    year INTEGER NOT NULL,
    quarter INTEGER NOT NULL CHECK (quarter BETWEEN 1 AND 4),

    ebitda_sum INTEGER DEFAULT 0,
    to_bank_sum INTEGER DEFAULT 0,
    condition_threshold INTEGER DEFAULT 0,
    condition_met BOOLEAN DEFAULT false,
    payout_available INTEGER DEFAULT 0,
    payout_done BOOLEAN DEFAULT false,

    updated_at TIMESTAMPTZ DEFAULT now(),

    UNIQUE (workspace_id, year, quarter)
);
```

### Таблица: years (агрегаты года)

```sql
CREATE TABLE years (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,
    year INTEGER NOT NULL,

    ebitda_sum INTEGER DEFAULT 0,
    total_bonus_sum INTEGER DEFAULT 0,
    paid_now_sum INTEGER DEFAULT 0,
    to_bank_sum INTEGER DEFAULT 0,
    condition_threshold INTEGER DEFAULT 0,
    condition_met BOOLEAN DEFAULT false,
    closed BOOLEAN DEFAULT false,
    closed_at TIMESTAMPTZ,

    updated_at TIMESTAMPTZ DEFAULT now(),

    UNIQUE (workspace_id, year)
);
```

### Таблица: ledger (журнал операций банка)

```sql
CREATE TABLE ledger (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,
    year INTEGER NOT NULL,

    operation_type TEXT NOT NULL CHECK (operation_type IN (
        'month_accrual',      -- начисление в банк за месяц
        'quarter_payout',     -- квартальная выплата
        'year_payout',        -- годовая выплата
        'manual_adjustment',  -- ручная корректировка
        'recalc_adjustment'   -- корректировка при перерасчёте
    )),

    month INTEGER,           -- для month_accrual
    quarter INTEGER,         -- для quarter_payout

    amount INTEGER NOT NULL, -- положительное = приход, отрицательное = расход
    balance_after INTEGER NOT NULL,

    comment TEXT,
    idempotency_key TEXT,    -- для предотвращения дублей

    created_by UUID REFERENCES auth.users(id),
    created_at TIMESTAMPTZ DEFAULT now(),

    UNIQUE (workspace_id, idempotency_key)
);

CREATE INDEX idx_ledger_workspace_year ON ledger(workspace_id, year);
```

### Таблица: audit

```sql
CREATE TABLE audit (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID REFERENCES workspaces(id) ON DELETE CASCADE,

    entity_type TEXT NOT NULL, -- 'month', 'config', 'ledger', 'year_config'
    entity_id UUID,
    action TEXT NOT NULL,      -- 'create', 'update', 'delete', 'payout'

    old_values JSONB,
    new_values JSONB,

    user_id UUID REFERENCES auth.users(id),
    created_at TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_audit_workspace ON audit(workspace_id, created_at DESC);
```

## A5. Стратегия расчётов

### Выбранный подход: RPC-функции на сервере

**Обоснование:**
1. **Консистентность** — все расчёты выполняются в одной транзакции
2. **Идемпотентность** — проверки уникальности на уровне БД
3. **Безопасность** — бизнес-логика не доступна клиенту
4. **Дебаг** — логирование в audit внутри той же транзакции
5. **Производительность** — один запрос вместо множества

### Основные RPC-функции

```sql
-- Пересчёт года (вызывается при изменении месяца или конфигурации)
recalculate_year(p_workspace_id UUID, p_year INTEGER)

-- Выполнение квартальной выплаты
execute_quarter_payout(p_workspace_id UUID, p_year INTEGER, p_quarter INTEGER)

-- Выполнение годовой выплаты и закрытие года
execute_year_payout(p_workspace_id UUID, p_year INTEGER)

-- Ручная корректировка банка
adjust_bank(p_workspace_id UUID, p_year INTEGER, p_amount INTEGER, p_comment TEXT)

-- Инициализация года (создание 12 месяцев)
init_year(p_workspace_id UUID, p_year INTEGER)
```

### Алгоритм пересчёта года

```
1. Получить активную конфигурацию для года
2. Получить все месяцы года, отсортированные по month
3. Получить начальный баланс банка (carryover или 0)
4. Для каждого месяца 1..12:
   a. Определить конфигурацию (по effective_from_month)
   b. Рассчитать monthly_base, monthly_threshold
   c. Рассчитать retention
   d. Рассчитать growth_bonus
   e. Рассчитать total_bonus, paid_now, to_bank
   f. Рассчитать bank_balance_after = previous_balance + to_bank - payouts_this_month
   g. Обновить запись месяца
5. Пересчитать агрегаты кварталов
6. Пересчитать агрегаты года
7. Записать в audit
```

## A6. RLS-политика

### Принципы

1. Пользователь видит только данные своих workspaces
2. Админ может изменять, viewer только читать
3. Закрытые года/месяцы защищены от изменений

### Политики

```sql
-- workspaces: видеть свои
CREATE POLICY "Users can view own workspaces" ON workspaces
    FOR SELECT USING (
        id IN (SELECT workspace_id FROM memberships WHERE user_id = auth.uid())
    );

-- months: видеть свои workspace
CREATE POLICY "Users can view workspace months" ON months
    FOR SELECT USING (
        workspace_id IN (SELECT workspace_id FROM memberships WHERE user_id = auth.uid())
    );

-- months: изменять только админы, если не locked и год не closed
CREATE POLICY "Admins can update unlocked months" ON months
    FOR UPDATE USING (
        workspace_id IN (
            SELECT workspace_id FROM memberships
            WHERE user_id = auth.uid() AND role = 'admin'
        )
        AND NOT locked
        AND NOT EXISTS (
            SELECT 1 FROM years
            WHERE years.workspace_id = months.workspace_id
            AND years.year = months.year
            AND years.closed = true
        )
    );

-- Аналогичные политики для других таблиц...
```

### Назначение роли админа

- Создатель workspace автоматически получает роль `admin`
- Админ может приглашать других пользователей и назначать роли
- В MVP: один workspace на пользователя, создатель = единственный админ

Интерфейс выполнен в стиле **Notion-like минимализма** — спокойная деловая эстетика, ориентированная на работу с табличными данными.

## A10. Принятые решения и допущения

### Архитектура

1. **Multi-tenant через workspace_id** — каждый workspace изолирован, RLS обеспечивает безопасность.

2. **Расчёты в RPC-функциях** — вся бизнес-логика на сервере для консистентности и безопасности. Клиент только отображает данные и вызывает RPC.

3. **Версионирование конфигураций с привязкой к году и месяцу** — используется модель `year_configs` с `effective_from_month`, что позволяет менять настройки в середине года.

4. **Идемпотентность выплат через idempotency_key** — формат ключа: `{workspace_id}:{year}:Q{quarter}:payout` или `{workspace_id}:{year}:year_payout`. Уникальный constraint предотвращает дубли.

### Бизнес-логика

5. **При смене конфигурации — пересчёт без отката выплат** — если конфигурация меняется после выплаты, выплата НЕ откатывается автоматически. Создаётся информационная запись в ledger с типом `recalc_adjustment` и комментарием о расхождении. Админ может вручную скорректировать.

6. **Отрицательная EBITDA допустима** — retention и growth будут 0, это валидное состояние.

7. **Пустые месяцы (NULL EBITDA)** — расчётные поля = 0, месяц помечен как "без данных". Квартальная/годовая выплата недоступна при наличии пустых месяцев в периоде.

8. **Округление математическое** — `ROUND()` в PostgreSQL, результат в целых рублях.

9. **Перенос остатка на следующий год** — НЕ реализуется в MVP. Каждый год начинается с нулевого банка. (Упрощение для MVP; можно добавить позже через manual_adjustment.)

### UX

10. **Один workspace на пользователя в MVP** — упрощение. Приглашение других пользователей не реализуется.

11. **Notion-like стиль** — светлый минималистичный интерфейс, таблицы с inline-редактированием, спокойные цвета.

12. **Подтверждения для выплат и закрытия года** — модальные окна с явным предупреждением.

13. **Русский язык везде** — интерфейс, сообщения об ошибках, подсказки.

### Технические

14. **Vite + React + TypeScript** — современный стек, быстрая разработка.

15. **Минимальный CSS без тяжёлых фреймворков** — собственные компоненты для контроля над стилем.

16. **Supabase Auth с email/password** — простейший вариант аутентификации для MVP.

17. **Хранение tiered_growth_json как JSONB** — гибкость, валидация на уровне приложения.
