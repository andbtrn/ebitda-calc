# PM Agent: Спецификация

## Общая концепция

### Цель
AI-агент для разгрузки Project Manager в аутсорс-команде. PM тратит 20% времени вместо 100%, может вести 2-3 проекта.

### Контекст
- Команда: ~10 человек
- Методология: гибрид Scrum/Kanban
- Инструменты: Jira, Telegram, NocoDB
- Клиент: команда внедрения создаёт задачи в бэклоге

### Принцип работы
Агент работает как сотрудник, который приносит артефакты (документы) на согласование PM. PM либо принимает, либо возвращает на доработку.

## Сценарий 1: Отчёт по спринту

### Описание
Агент собирает статусы задач из Jira, уточняет устаревшие через Telegram, формирует отчёт для PM.

### Параметры

| Параметр | Значение |
|----------|----------|
| Сбор из Jira | Раз в день, настраиваемое время |
| Порог устаревания | 2 дня без изменений |
| Интервал напоминаний | 45 минут |
| Количество напоминаний | 3 |
| После 3-го напоминания | Эскалация PM |
| Формат отчёта | По шаблону, PDF/DOCX |
| Язык | Русский |

### Поток данных

```
┌──────────┐
│   JIRA   │
└────┬─────┘
     │ раз в день (настраиваемое время)
     ▼
┌──────────┐
│  NocoDB  │ ← таблица sprint_tasks
└────┬─────┘
     │ проверка: есть устаревшие?
     ▼
┌──────────────────────────────────┐
│          TELEGRAM                │
│  Разработчику (если устарело):  │
│  ┌────────────────────────────┐  │
│  │ PROJ-502: Интеграция CRM   │  │
│  │ Статус не обновлялся 3 дня │  │
│  │                            │  │
│  │ [Готово] [В работе] [Блок] │  │
│  └────────────────────────────┘  │
└────────────┬─────────────────────┘
             │ ответы записываются
             ▼
       ┌──────────┐
       │  NocoDB  │ ← таблица status_updates
       └────┬─────┘
            │ по расписанию или запросу
            ▼
┌───────────────────────────────────┐
│         ГЕНЕРАЦИЯ ОТЧЁТА          │
│  NocoDB + Jira → Шаблон → PDF     │
└────────────┬──────────────────────┘
             ▼
┌───────────────────────────────────┐
│           PM в Telegram           │
│  ┌─────────────────────────────┐  │
│  │ 📄 Отчёт Sprint 14 готов    │  │
│  │ [Открыть] [PDF] [DOCX]      │  │
│  └─────────────────────────────┘  │
└───────────────────────────────────┘
```

### Кнопки для разработчика

**Уровень 1:**
- ✅ Готово
- 🔄 В работе
- 🚫 Блокер

**Уровень 2 (при "В работе"):**
- Жду ревью
- Жду ответа
- Тестирую
- Пишу код
- Другое

**Уровень 2 (при "Блокер"):**
- Жду коллегу
- Жду клиента
- Техническая проблема
- Другое

При "Другое" — запрос свободного текста.

### Логика напоминаний

```
Устаревший статус (2+ дня)
     │
     ▼
Напоминание #1 ──► Ответ? ──► Да ──► Записать ✓
     │                  │
     │ 45 мин           └─► Нет
     ▼                        │
Напоминание #2 ──► Ответ? ────┘
     │                  │
     │ 45 мин           └─► Нет
     ▼                        │
Напоминание #3 ──► Ответ? ────┘
     │                  │
     │ 45 мин           └─► Нет
     ▼                        │
Эскалация PM ◄────────────────┘
```

## Технические требования

### Интеграции
- Jira REST API
- Telegram Bot API
- NocoDB API

### Генерация документов
- Шаблон DOCX с плейсхолдерами
- Экспорт в PDF

### Scheduler
- Cron-подобное расписание
- Настраиваемое время сбора из Jira
- Триггер генерации отчёта (по расписанию / по запросу)
